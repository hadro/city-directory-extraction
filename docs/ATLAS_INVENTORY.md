# Atlas inventory: Brooklyn and Manhattan, 1850-1920

Date: 2026-11-14 (research run; some fetches finished 2026-11-15)

Method: web search plus fetching pages. "opened" means I fetched the page or JSON myself. "snippet" means the fact comes only from a search-result summary. "not found" means I looked and could not establish it. Nothing here was downloaded beyond small JSON manifests.

Two findings change the plan, so they come first.

1. NYPL's Map Warper (maps.nypl.org/warper) is retired. `maps.nypl.org/warper/layers/860` and `/layers/1051` both return a 301 redirect to an Archive-It web-archive capture of the Warper home page dated 2021-05-20 (opened). That page carries NYPL's notice: "As of April 2021, Mapwarper will no longer be updated by NYPL, and will soon be archived," and says embedded views will stop working. So the Space/Time layer numbers below are history, not live services. NYPL says it keeps "all contributions and data", but I found no public export of the control points.
2. NYPL serves every sheet through IIIF, and the Perris Brooklyn plates are separate, one-canvas items. Each plate has its own manifest at `https://api-collections.nypl.org/manifests/<UUID>` (IIIF Presentation 3, opened) and an image service at `https://iiif.nypl.org/iiif/3/<imageID>` (opened: `.../1268449/info.json` is ImageService3, level2, 6141 x 4620). That is enough to feed Allmaps, which takes a manifest or an image-service URL.

## danvk/mapsnap

Opened: `github.com/danvk/mapsnap`, `mapsnap.org`, `mapsnap.org/runs/v2.0/`, the commit list, and one gallery file.

- What it does: automatically georeferences Sanborn fire-insurance sheets. It runs OCR (EasyOCR) for street labels, matches them to OpenStreetMap street names for the area, extrapolates streets to intersections that become control points, fits a four-parameter model (translation, scale, rotation) with a RANSAC-style search, and builds a clipping mask following the street grid so each block shows on one sheet only.
- Inputs: scanned page images; a IIIF manifest (for loc.gov, downloaded by hand in a browser because of Cloudflare); an OSM relation id for the city or county, e.g. `r1234567`; for OIM data, an S3 image prefix. Command: `uv tool install mapsnap-cli`, then `mapsnap run-loc mymap r1234567`.
- Outputs: a IIIF Georeference AnnotationPage (W3C annotations, `motivation: georeferencing`, GCP FeatureCollection with an order-1 polynomial transform, SvgSelector mask per sheet), viewable in Allmaps; plus sidecar files `boxes.json`, `streets.json`, `georef.json`, `georef-snap.json`. I opened the Brooklyn 1939 vol. 2 file at `raw.githubusercontent.com/danvk/mapsnap/main/gallery/brooklyn_ny_1939_vol_2.iiif.json` to confirm the structure.
- Brooklyn example: Brooklyn 1939, Vol. 2, page 19 (Pierrepont, Henry, Clinton streets). Allmaps viewer link in the README: `viewer.allmaps.org/?url=https%3A%2F%2Fraw.githubusercontent.com%2Fdanvk%2Fmapsnap%2Frefs%2Fheads%2Fmain%2Fgallery%2Fbrooklyn_ny_1939_vol_2.iiif.json`. README scores for the v2.0 run: Brooklyn 1939 vol. 1 = 87.2% (52 of 62 pages placed); mean over 20 development volumes 82.4%; 78.7% pooled over 689 scorable volumes.
- Limits stated in the README: fails where streets were reworked or renamed (Queens 1898 given as an example), short street names, Washington DC.
- Scope: LoC Sanborn collection only. The v2.0 run page says 30,611 volumes published out of 35,101; the site says about 7,820 places and 343,403 sheets placed. The run page does not list Brooklyn volumes, so I cannot say whether Brooklyn 1886-88 was placed. For our use that matters: the 1871 renumbering shows up in street renaming and block layout, and mapsnap says it struggles there, though Brooklyn's Court St grid has been stable.
- Maintenance: Apache-2.0; 402 commits; 115 open issues; 2 open PRs; 23 stars; no release tags shown. Most recent commits 2026-10-29, with activity 2026-10-24 to 10-29. Actively maintained as of this check.
- Not applicable to NYPL atlases without work: it expects Sanborn-style street-labelled sheets and a LoC manifest. It might work on Perris plates (streets are named on them) but the README makes no such claim.

## NYPL Building Inspector

- Tool and code: `github.com/NYPL/building-inspector` (opened). Rails app, Apache-2.0, 942 commits, 25 open issues; the page shows no last-commit date. It loads GeoJSON from NYPL's Map Vectorizer and has volunteers vote on geometry, colour, address and toponym. The README names Warper layers 859 and 860 for NYPL polygons: 859 is Perris 1857-62 Manhattan and 860 is Perris 1855 Brooklyn per the layer list above. The README has no list of processed layers or completion status.
- The 2013 NYPL Labs blog post (`live-legacy-admin.nypl.org/blog/2013/11/19/nypl-labs-building-inspector-brooklyn-api-open-source-edition`) says the next challenge after the 1857 Manhattan atlas was the 1855 Perris Brooklyn maps and that there is a GeoJSON API. I could not open the post itself (fetch failed); this is from a search snippet. I could not confirm that the 1857 atlas was "finished" or how far Brooklyn got.
- Where the data is published: the live site `buildinginspector.nypl.org` (including `/data` API) did not resolve in DNS when I tried (ENOTFOUND). The data was republished through NYPL Space/Time as `building-inspector` (buildings with year, layer and colour; addresses with house number, year, layer id and coordinates; a relations file), e.g. `s3.amazonaws.com/spacetime-nypl-org/datasets/building-inspector/building-inspector.objects.ndjson`. All of this is from Bert Spaan's tutorial page `github.com/bertspaan/tutorial-historical-addresses` (opened); I did not fetch the files. Sample address record: house number 20, valid 1857, layerId 859, mapId 7138. The tutorial also uses a Fulton Street example dated 1855, which hints at Brooklyn records, but it does not say so. Whether the S3 files still exist: not checked.
- Why it matters here: Building Inspector's address records are the closest thing to "house numbers read off an 1855 atlas, with coordinates". If the Brooklyn 1855 addresses exist, they are the pre-renumbering side of the 1871 comparison.

## NYC Open Data "Building Footprints (Historical)"

- Dataset id `ipkp-snf6`, titled BUILDING_HISTORIC on Data.gov (opened). Landing page `data.cityofnewyork.us/d/ipkp-snf6`. First published 2025-05-28; data last updated 2026-11-09 per Data.gov. Downloads: CSV, GeoJSON, KML, JSON via `data.cityofnewyork.us/api/v3/views/ipkp-snf6/...`. Documentation: `github.com/CityOfNewYork/nyc-geo-metadata/blob/main/Metadata/Metadata_BuildingHistoric.md` (opened).
- Contents: footprints of buildings demolished or significantly altered. They are moved here from the current footprints dataset when that happens. The record's LAST_STATUS_TYPE says which event (Demolition, Alteration). The older records "were not consistently updated".
- Fields (from the columns file, opened): the_geom (multipolygon), NAME, BIN, DOITT_ID, SHAPE_AREA, BASE_BBL, OBJECTID, CONSTRUCTION YEAR, DEMOLITION YEAR, FEATURE CODE, GEOM SOURCE, GROUND ELEVATION, HEIGHT ROOF, LAST_EDITED_DATE, LAST_STATUS_TYPE, MAP PLUTO BBL, Shape__Length. ALTERATION_YEAR is tracked but not published.
- Dates: CONSTRUCTION YEAR came from the Dept. of Finance RPAD database (0 or NULL = unknown); DEMOLITION YEAR is the year of demolition; LAST_EDITED_DATE is when the record was added, not the demolition date.
- For us: it records demolished buildings, but only modern ones (as the city's database knows them). Nothing says it goes back to 1871. It has BBL and BIN, so it is useful for tying present lots to the block, not for the 1871 house-number mapping. Time coverage is not stated.

## Best sheets for the 1871 renumbering

- Before 1871: Perris 1855 plate 33 (with plate 32 for the blocks north of it).
